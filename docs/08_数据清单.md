## 三、表结构

```sql
CREATE TABLE ticks(code TEXT, ts INTEGER, price REAL, bid REAL, ask REAL, vol REAL, oi REAL,
                   PRIMARY KEY(code, ts));
CREATE TABLE kline(code TEXT, period TEXT, ts INTEGER, o REAL, h REAL, l REAL, c REAL, v REAL,
                   PRIMARY KEY(code, period, ts));
CREATE TABLE forecasts(id INTEGER PRIMARY KEY AUTOINCREMENT, code TEXT, horizon TEXT, dir TEXT,
                       p_up REAL, target REAL, price REAL, score REAL, source TEXT, reason TEXT,
                       created_at INTEGER, due_at INTEGER, actual REAL, hit INTEGER);
CREATE TABLE seed_meta(key TEXT PRIMARY KEY, value TEXT);
```

与手机端 `Store`（`futures.db`）的表结构完全一致，因此可以直接 `ATTACH` 后整表导入。

## 四、导入逻辑

`db/SeedImporter.importIfNeeded()`：

1. 把 `assets/seed.db` 复制到 `cacheDir`；
2. 读 `seed_meta.version`，与 `Cfg.seedVersion()` 比较，**版本没变就跳过**；
3. `ATTACH DATABASE` 后执行
   `INSERT OR IGNORE INTO kline(code,period,ts,o,h,l,c,v) SELECT ... FROM seed.kline`；
4. 写入新的 `seed_version`，删除临时文件。

用 `INSERT OR IGNORE` 而不是 `REPLACE`：手机上已经采集到的同 key 记录（通常比预置包新）不会被回退覆盖。
升级 APK 时若预置库版本更新，会自动补入新数据，老数据保留。

## 五、秒级点为什么是空的

公开接口不提供历史秒级行情（付费源才有）。App 采用「运行即累积」：每次刷新写一条 `ticks`，
`Engine` 里 `store.prune(30)` 只保留 30 天。**不拿分钟线伪造秒级点**，否则会污染波动率与命中率统计。

## 六、重新生成

```bash
python3 scripts/build_seed.py            # 重新抓取并覆盖 assets/seed.db
python3 scripts/build_seed.py --skip-minute   # 只要日线（体积更小）
bash android/build-apk.sh                # 重新打包，预置库随 APK 分发
```

抓取间隔 0.6s，单个周期失败不影响整体；`seed_meta.version` 取构建时间 `yyyyMMddHHmm`，
每次重建都会变新，已安装用户下次启动即可自动补入。
