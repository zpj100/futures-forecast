# v2.7.0 服务端化与启动自检

> 把 App 核心能力搬到服务端、让服务端成为唯一真源；服务端启动时按期货交易日历自动补全缺失的 1m 数据；默认端口改为 8123。

## 1. 三个关键决策

1. **Android 端保留独立 App**：两路并存，不改为 WebView 壳、不废弃。Web 前端（backend/app/static）承担桌面/局域网浏览，App 继续作为移动端入口，默认服务端地址指向 `8123`。
2. **启动自检补全口径：期货交易日历**：日盘 `9:00–15:00`（含 `10:15–10:30`、`11:30–13:30` 休市子窗口）、夜盘 `21:00–次日 01:00`（跨午夜、锚定交易日）、跳过周末；节假日未建模。
3. **Web 界面四 tab 全覆盖**：行情 / 预测 / 历史 / 设置。

## 2. 服务端成为唯一真源

- `backend/app/static/` 重写为四 tab 结构：行情（8 周期 1s/30s/1m/5m/15m/30m/60m/1d + 三品种归一化对比）、预测（七档 + 大模型框）、历史（命中率表）、设置（主题 / 刷新 / LLM / 数据库与启动自检面板 / 数据覆盖 / 关于）。
- 所有时间序列统一为**毫秒整数** `ts`、统一**自然时间桶起点**口径，与既有 `/api/app/*` 契约对齐。
- 预测七档 `APP_HORIZONS = 1m/5m/15m/30m/4h/8h/1d`，与 Android `Forecaster.HORIZONS` 一致。

## 3. 交易日历 `backend/app/calendar.py`

- `trading_sessions(start_dt, end_dt)` 枚举区间内全部交易时段（含跨午夜夜盘）。
- 夜盘锚定**交易日** `cursor`：`ns = cursor-1 天 21:00`，`ne = cursor 01:00` —— 保证周五无夜盘、周日夜盘（21:00 周日 → 01:00 周一）正确生成。
- `expected_minute_count(start, end)`、`session_coverage_note()` 供自检与接口说明复用。

## 4. 启动自检补全 `backend/app/autofill.py`

- 模块全局 `LAST_REPORT`；`get_report()` 供 `/api/health`、`/api/autofill/status` 读取。
- `check_and_fill()`：`lifespan` 在 `store.init()` 后、`collector.run_all()` 前调用（try/except，**不阻塞 API 启动**）。
- 逐品种 `_scan_product()`：取库内最新 1m `ts` → 枚举交易时段 → `minute_count_in_range` 比对覆盖率；窗口内缺失列 `missing`、窗口外列 `unrecoverable`（Sina 1m 固定 1023 根物理不可补，如实标注）。
- 窗口内缺口触发 `_fetch_and_upsert()`（一次 `sina.fetch_all_minute(1)` + upsert + `sync_multi_incremental`）后重扫；结果写入 `LAST_REPORT`。
- 常量：`_SCAN_DAYS=30`、`_REACH_MINUTES=1023`、`_COVERAGE_THRESHOLD=0.6`、`_FILL_RATE=0.02`。

## 5. 服务端大模型 `backend/app/llm.py`

- 配置存 `DATA_DIR/llm.json`（`{base, model, key}`），文件优先于环境变量 `FF_LLM_*`；`_save` 时 `chmod 600`。
- `get_config()` 返回 `{base, model, hasKey}`；`set_config(base, model, key)` 支持 `__CLEAR__` 哨兵清除 key。
- `analyze(code, period)` 调 `/chat/completions`，**密钥只留服务端、绝不写仓/库/前端**。
- 路由：`GET/POST /api/llm/config`、`POST /api/llm/analyze`。

## 6. 预测命中率历史 `/api/history`

- `store.forecast_log` 表（code, ts, horizon, hmin, dir, score, price；主键 `(code,ts,horizon)` 幂等）。
- `collector` 每轮 `tick_klines` 调用 `_log_forecast()` 把七档预测落库，并 `truncate_forecast_log(90 天前)` 限增长。
- `_history_for_code()`：`forecast_log_since` 取记录 → `price_at_or_after(ts + minutes*60000)` 取实际价 → 比对方向算命中率。
- **注意**：命中率需对应 horizon 到期后有实际价可比对；短周期（1m/5m/15m/30m）在服务运行数分钟内即可出数，4h/8h/1d 需数小时/天。未到期或窗口外缺数据则 `total=0`、`accuracy=null`，属正常。

## 7. 端口 8123

- `run.sh` 默认 `--port "${PORT:-8123}"`；`run-lan.sh` 示例 `PORT=8123`、`netsh`/防火墙示例同步改 8123。
- Android `assets/app.js` 默认 `server.base`、`db.base` 与帮助文案 `:8000 → :8123`（3 处）。
- 所有文档（`README.md`、`docs/API.md`、`docs/11_*` 等）端口引用统一改为 8123。

## 8. 启动与验证

```bash
cd ~/projects/futures-forecast
bash run.sh                 # 默认 http://127.0.0.1:8123，/docs 为接口文档
# 局域网：bash run-lan.sh（0.0.0.0:8123）+ Windows netsh 转发 + 防火墙放行 8123

curl http://127.0.0.1:8123/api/health        # 含 autofill 自检报告
curl http://127.0.0.1:8123/api/app/kline?code=AL&period=1m&limit=3
curl http://127.0.0.1:8123/api/history?code=AL&days=30
curl http://127.0.0.1:8123/api/llm/config
curl http://127.0.0.1:8123/api/autofill/status
```
