# 开源期货预测与量化算法借鉴

记录 v2.0.0 改造前的调研结论：看了哪些开源项目、哪些思路被采纳、哪些明确不采纳。
目的不是堆概念，而是解释「为什么手机上跑的是现在这套模型」。

调研时间：2026-11。检索范围：GitHub / Gitee 上活跃度较高的量化框架与 CTA 策略库。

---

## 一、主流框架定位对比

| 项目 | 定位 | 语言 | 与本项目的关系 |
|------|------|------|----------------|
| **vn.py (VeighNa)** | 国内期货 CTA 全栈平台，CTP 网关成熟 | Python + C++ | 借鉴其**指标组合与方向过滤**思路；不移植（依赖 CTP、Qt、体量大） |
| **Qlib**（微软） | AI 量化研究平台，Alpha158 因子库 | Python | 借鉴**滚动训练 / 走向外验证**的评估纪律；因子库不适用单品种高频 |
| **Backtrader** | 事件驱动回测，文档友好 | Python | 借鉴**事件驱动与滑点/手续费建模**；2019 年后停更，不引入 |
| **freqtrade** | 加密 CTA，开箱即用 | Python | 借鉴**信号 + 风控分层**的工程结构 |
| **QUANTAXIS** | 一体化平台，数据层强 | Python | 数据清洗思路可参考，部署过重 |
| **WonderTrader / Hikyuu** | 高性能 C++ 内核 | C++ | 性能思路，手机端不需要 |

结论：**没有现成框架能塞进 APK**。它们的价值在于方法论，而不是代码。

## 二、被采纳的四条

### 1. 信号库 + 走前验证（来自 Qlib / vn.py 的评估纪律）

不用单一指标拍方向，而是维护一个小信号库：

- `trend`：EMA5 / EMA20 交叉
- `reversion`：RSI 超买超卖反转
- `boll`：布林 Z-score 均值回归
- `momentum`：近 N 期动量延续

每个信号都在**尾部 45% 样本**上做走向外验证，算真实方向命中率。
命中率 ≤ 50% 的信号权重直接归零——这是 Qlib「滚动训练 + 样本外评估」思路的简化版。

### 2. 权重与「证据量」挂钩，而不是与「自信程度」挂钩

```
weight = max(0, hit - 0.5)        // 只有超额胜率才算权重
conviction = Σ(w × signal) / Σw   // 方向一致性
evidence  = min(Σw / 0.25, 1)     // 有多少验证过的优势在支撑
edge = conviction × σ × √step × 0.5 × evidence
```

概率上限随证据总量收缩：`cap = 0.5 + 0.35 × min(Σw/0.20, 1)`。
**证据不足时不给高概率**，这是从 vn.py 社区讨论里最常被忽略的一条。

### 3. 多周期一致性作为风控过滤器

六周期（1m/5m/10m/1h/8h/1d）各自出方向，再按置信度加权。
当 ≥2 个高置信周期方向冲突时，建议文本里直接提示「多周期方向不一致，优先降低杠杆」。
这对应 CTA 里常见的「大周期定方向、小周期定入场」，只是这里退化为提示而非自动下单。

### 4. 波动率自适应

用 ATR% 与 20 期收益率标准差衡量当前波动，波动偏高时降低建议仓位、放宽止损。
来自 freqtrade / vn.py 的 ATR 止损实践。

## 三、明确不采纳的

| 方案 | 不采纳原因 |
|------|-----------|
| LSTM / Transformer 端到端预测 | 手机上推理成本高、样本少极易过拟合，且无法解释 |
| Alpha158 因子库 | 为横截面选股设计，单品种时序用不上 |
| 高频做市 / 盘口微观结构 | 公开行情接口只有快照，没有逐笔与委托队列 |
| 在线自动调参 | 每次调参都可能拟合噪声；固定参数 + 走向外验证更诚实 |
| 实盘下单 | 本项目只做研究展示，不接交易接口 |

## 四、与 Python 后端的关系

后端 `backend/app/model/forecaster.py` 保留了完整实现，包括 numpy 手写岭回归
（11 维特征、正规方程求解）。手机端 **不做在线岭回归训练**，理由：

1. 1200 根 1 分钟样本上训练 11 维岭回归，增益远小于信号融合；
2. 训练耗时与电量代价在手机上不划算；
3. 后端 README 的实测也显示，日线各信号胜率约 0.5，岭回归没有稳定超额。

因此 APK 内的 `Forecaster.java` 只移植「信号库 + 走前验证 + 证据收缩」这一段，
口径与后端一致：**优势不明显就输出「震荡」**，不用掷硬币的准确率装自信。

## 五、大模型的位置

大模型（默认 DeepSeek，可切换任意 OpenAI 兼容端点）**不替代**量化模型，而是并列的第二意见：

- 输入：现价、六周期结论、技术指标、近期价格采样（60 点）
- 输出：结构化 JSON（方向 / 置信度 / 目标区间 / 依据 / 风险 / 操作建议）
- 展示：与量化结论并列，标注来源，方便对照谁更靠谱
- 留档：写入 `forecasts` 表，`source='llm'`，到期同样回填实际价算命中率

长期看，这张表本身就是最有价值的资产：**能算出量化和大模型谁的命中率更高**。
