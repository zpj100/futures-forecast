# v2.6.0 手机数据库修复 + 服务端同步

> 本文件聚焦 v2.6.0 解决的三件事：① 手机同步历史数据「显示无缺失/新增 0 根」；② 本地 WSL 服务端启动与手机可达；③ 手机↔服务端数据库双向同步。

## 一、手机同步「0 根」的根因与修复

### 根因（两处叠加）
1. **回补基准被 7 天窗口截断**：`Engine.syncHistory` 的 `buildBatches()` 之前只收集「近 7 天窗口」内的 bar。源站各周期可给的历史远长于 7 天（5m≈15 天、15m≈2 月、30m≈3 月、60m≈6 月），窗口内无缺失就永远 `added=0`，看起来像没更新。
2. **旧版本双时间戳残留**：v2.3/v2.4 的 `incrementalMinute` 曾把 1m 派生聚合成「自然桶起点」ts 写进同一张 `kline`，与预置库「源站段末」ts 并存；`SeedImporter` 在本地有数据时直接跳过，不清理。

### 修复
- `buildBatches()` 改为收集 `j.bars`（源站整段序列）中「本地没有的 ts」；`analyze()` 仍按 7 天窗口产出体检报告（`check`），但**不参与回补**。结果：5m/15m/30m/60m 补到源站可给的最长历史，1d 补 180 天，1m 仍 1023 根。
- 报告新增 `full_window_bars / repaired_bars / per_period`：明确写「本次写入 N 根 / 覆盖 M 个周期」；`wroteBars==0` 时追加说明「更早历史请从服务端同步」。
- **首次启动自动迁移**：`Engine.start()`（后台线程）调用 `Store.migrateLegacyBars()`，对照 `assets/seed.db` 删除本地 5m/15m/30m/60m 中「落在 seed 区间但不在 seed ts 集合」的旧口径残留行（用临时表 `seed_ts` + `NOT IN` 子查询），结果存 `db_migrated_rows`，只跑一次（键 `db_migrated_260`）。
- 设置页新增「诊断」区与「重建本地数据库」按钮（`Bridge.rebuildLocalDb()`，后台清 kline→重导预置库→`reloadCaches`→前端刷新），兜底用户手动清零。

## 二、WSL 服务端启动与手机可达

### 启动（0.0.0.0 监听）
```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
bash run-lan.sh        # 内部 exec env FF_HOST=0.0.0.0 PORT=8123 bash run.sh
```
> 不改 `run.sh` 默认值（仍为 127.0.0.1）；`run-lan.sh` 仅通过环境变量覆盖为 0.0.0.0。

### Windows 侧让手机可达（管理员 PowerShell，一次即可）
```powershell
# 1) 端口转发：WSL2 是独立虚拟网络，需把 Windows 8123 转发到 WSL2 的 8123
$WSL = (wsl -d Debian -e hostname -I).Split()[0]
netsh interface portproxy add v4tov4 listenport=8123 listenaddress=0.0.0.0 connectport=8123 connectaddress=$WSL
# 2) 防火墙放行 8123 入站
New-NetFirewallRule -DisplayName "futures-forecast LAN 8123" -Direction Inbound -Protocol TCP -LocalPort 8123 -Action Allow -Profile Private
```
重启 WSL 后 `$WSL` 可能变化，需重新执行第 1 步（用新 IP）。

### 手机填写的地址
设置页 → 数据库同步 → 地址填 `http://<Windows 局域网 IP>:8123`（例如本机实测 `http://10.76.188.113:8123`）。
- 应用层 `Bridge.isValidServerBase` 仅允许 `127.0.0.1/localhost` 与 `10./172.16-31./192.168.` 私有网段（必须显式端口），公网 http 一律拒绝；https 允许。
- `network_security_config.xml` 平台层放开明文（仅承载上述白名单内的私有网段 http），对照开关默认关，API 24+ 以该 XML 为准。

## 三、手机↔服务端数据库双向同步

### 服务端接口（新增，独立分表，不影响既有路由）
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/db/status` | 三品种×六周期根数/首末 ts（统一毫秒整数）、`app_table` 分表统计、`note` |
| GET | `/api/db/export?code=&period=&since=&limit=300` | 分页导出；`since` 毫秒（0=全部）；`has_more`/`next_since` |
| POST | `/api/db/import` | body `{code,period,bars,source:"app"}`，写**新分表 `kline_app`**（不与既有 `kline_min/kline_day` 混），幂等（重复 added=0） |

导出口径：`1m/1d/1s/30s` 来自服务端自身库；**5m/15m/30m/60m 只读手机上传的 `kline_app` 分表**（源站段末口径），避免污染服务端既有自然桶聚合数据。

### 手机侧流程（`app.js` 设置页「与服务端同步」）
1. 取 `N.localDbStatus()` 与 `N.serverGet('/api/db/status')` 做对照。
2. **下拉**：三品种×八周期，按本地 `max(ts)` 翻页 `serverGet('/api/db/export')` → `N.importBars()`，单组合最多 30 批。
3. **上推**：三品种×六周期，`N.exportBars()` 翻页 → `N.serverPost('/api/db/import')`。
4. 进度条显示「第 N/M 批 · 下拉/上推 · 品种 周期」，单批失败记 warn 继续，幂等，结束 `pull(true)`。
5. 「测试连接」仅 `setServer(base,false)` 配地址、`serverGet('/api/db/status')` 验证，不开启对照开关。

### 跨组契约（严格对齐）
- `Bridge`：`localDbStatus()/exportBars(code,period,since,limit)/importBars(code,period,barsJson)/serverPost(path,body)/rebuildLocalDb()/setServer(base,on)`；`serverGet/serverPost` 不再要求 `server_on`，只要求 `server_base` 合法。
- `Store`：`migrateLegacyBars(ctx)/countLegacyBars()/clearKline()`。
- `Backend`：`db_sync.py` 的 `kline_app(code,period,ts,o,h,l,c,v,source)`，主键 `(code,period,ts)`，PRIMARY KEY。

## 四、验证
- `node --check app.js`、`py_compile` 全过；内存 ASGI 回归：既有 12+ 路由 + 新增 3 路由全 200；`/api/db/import` 同一批连做两次 `added=1→0`；导出/导入 5m 往返正常。
- 服务端实际以 `0.0.0.0:8123` 运行，Windows 侧 `127.0.0.1:8123` 与局域网 `10.76.188.113:8123` 均返回 200（健康/状态接口）。
- Gradle `BUILD SUCCESSFUL`；`versionCode=260 / versionName=2.6.0`，签名与 v2.5.0 一致，覆盖安装保留本地数据。

## 五、残余风险 / 说明
- 真机未联网实测（本机无第二台设备）；手机需与 Windows 主机同 LAN，且 WSL 重启后需重设转发 IP。
- 1m 的 7 天前历史源站无数据，仍不可补、不伪造；更早历史依赖「服务端同步」获取手机上传段。
- `kline_app` 分表目前只由手机写入，多端同账号不同步冲突（按 ts 主键 REPLACE 覆盖）。
